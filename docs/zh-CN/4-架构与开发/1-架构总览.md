# 架构总览

> 面向开发者：Snow App 的整体架构设计、分层职责、通信链路与关键机制。
> 配合阅读：[数据存储位置](4-数据存储位置.md)、[开发者指南](2-开发者指南.md)。

## 1. 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 渲染进程 | React 18 + TypeScript + Vite | UI、状态管理（React Hooks）、i18n（zh-CN/en/zh-TW） |
| 主进程 | Electron 37 + TypeScript | 窗口/生命周期、IPC、系统集成（PTY/SSH/更新器/托盘） |
| 原生层 | Rust + napi-rs | AI 引擎、MCP 工具、SQLite 存储、代码库索引 |
| 数据库 | SQLite（rusqlite，WAL） | 单文件 `~/.snowapp/snowapp.db` |
| 构建 | electron-vite + cargo + electron-builder | 三入口打包 + 平台原生 `.node` |

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ ① Renderer（React）                                           │
│    src/renderer/  components / hooks / i18n / utils           │
│    通过 window.snow.*（contextBridge 暴露）调用能力            │
└───────────────┬──────────────────────────────────────────────┘
                │ window.snow.* （仅 IPC 通道，无 Node 能力）
┌───────────────▼──────────────────────────────────────────────┐
│ ② Main（Electron 主进程）                                     │
│    src/main/                                                  │
│    ├── ipc/handlers/     IPC 处理器（业务编排）                │
│    ├── native/           Rust 桥（Proxy + storageReady 门控）  │
│    ├── app/              启动引导 / 窗口 / 会话代理 / 托盘      │
│    ├── pty/  ssh/  updater/  plugins/  snowCli/  settings/    │
└───────────────┬──────────────────────────────────────────────┘
                │ napi-rs 调用（同步/异步 binding）
┌───────────────▼──────────────────────────────────────────────┐
│ ③ Native（Rust）                                              │
│    native/src/                                                │
│    ├── exports/   napi 导出入口（storage/api/codebase/…）      │
│    ├── api/       AI 供应商适配（anthropic / gemini / responses）│
│    ├── mcp/       内置 MCP 服务器 + 外部 MCP 客户端             │
│    ├── storage/   SQLite 存储层（21+ 表）                      │
│    ├── prompt/    系统提示词                                   │
│    └── hooks/     生命周期钩子                                 │
└──────────────────────────────────────────────────────────────┘
```

### 分层原则

- **渲染进程无 Node 权限**：所有系统能力（文件、进程、数据库、网络）都必须经过 preload 暴露的 `window.snow.*` API，禁止在 renderer 直接 require Node 模块。
- **主进程是编排层**：IPC handler 负责业务编排（参数校验、组合 native 调用、返回序列化结果），不直接持有数据库。
- **Rust 是能力层**：数据库访问、AI 请求、MCP 工具执行、代码库索引全部在 native 侧，TypeScript 侧只做转发。

## 3. 通信链路

### 3.1 调用链（Renderer → Rust）

```
React 组件
  → window.snow.conversationApi.listChatConversations(dirId)
    → src/preload/modules/conversationApi.ts  (ipcRenderer.invoke)
      → src/main/ipc/handlers/conversationHandlers.ts  (ipcMain.handle)
        → native.conversations.listChatConversations(dirId)   ← nativeBridge Proxy
          → native/src/exports/storage.rs  (napi 导出)
            → native/src/storage/services/chat_conversations.rs  (rusqlite)
              → ~/.snowapp/snowapp.db
```

### 3.2 preload 桥（contextBridge）

`src/preload/index.ts` 将各 `modules/*Api.ts` 展开后通过
`contextBridge.exposeInMainWorld("snow", api)` 暴露。类型定义在
`src/preload/types/`，renderer 从 `@preload` 导入类型。

### 3.3 主进程 → Rust 的门控（关键机制）

`src/main/native/nativeBridge.ts` 用 **Proxy 包装**原生绑定：任何 native
方法调用都会先 `await storageReady`（数据库初始化完成的 Promise），
因此 **窗口可以立即显示**，SQLite 在后台初始化，IPC handler 无需各自加锁：

```ts
const wrapWithStorageGate = (binding) => new Proxy(binding, {
  get(target, prop, receiver) {
    const value = Reflect.get(target, prop, receiver);
    if (typeof value !== "function") return value;
    return (...args) => storageReady.then(() => value.apply(target, args));
  },
});
```

### 3.4 事件流（Native → Renderer）

AI 流式输出走 `src/main/app/sessionProxy.ts` 的会话代理：native 通过
napi callback / event emitter 推送 token、工具调用与指标事件，主进程
转发到对应的 WebContents，renderer 侧 `useAgentLoop` 等 hooks 消费。

## 4. Rust 原生层详解

### 4.1 napi 导出入口（native/src/exports/）

| 模块 | 职责 |
|------|------|
| `storage.rs` | 存储服务导出（会话、配置、备忘、插件、导入资源…） |
| `api.rs` | AI API 调用导出（chat / stream / theme palette） |
| `codebase.rs` | 代码库索引（embedding、chunk、搜索） |
| `engine.rs` | 会话引擎（agent loop） |
| `git.rs` | Git 操作（状态/提交/差异，供 UI 使用） |
| `terminal.rs` | PTY 终端支持 |
| `checkpoint.rs` | 文件变更检查点 |
| `updater.rs` | 应用更新检查 |
| `sphere_layout.rs` | 代码库 3D 球面布局（可视化） |

> `scripts/build-native.cjs` 执行 cargo build 后，按平台 triple 将产物
> 复制为 `snow_native.<platform>.node`（napi-rs 命名约定）。

### 4.2 MCP 层（native/src/mcp/）

- **servers/** — 内置 MCP 服务器（给 AI agent 的工具集）：
  `bash`（命令执行，支持 detach 后台）、`browser`、`grep`、`filesystem`、
  `codelens`（代码诊断）、`config`（配置读写）、`skills`、`skills_installer`、
  `sub_agents`、`todo`、`app_control`、`codebase`、`remote_workspace`（SSH）。
- **external/** — 外部 MCP 客户端（连接用户配置的 MCP 服务器）。
- **protocol/** — MCP 协议（JSON-RPC）实现。
- **privacy_mask/** — 隐私掩码（敏感信息过滤）。

### 4.3 AI 供应商适配（native/src/api/）

`anthropic/`（Claude）、`gemini/`（Gemini）、`responses/`（OpenAI
Responses API）、`chat/`（OpenAI Chat Completions）——统一收敛到
`api/chat/payload.rs` 的规范工具调用结构，对话模式修复与工具调用
规范化在此层完成。

### 4.4 存储层（native/src/storage/）

- `database.rs` — 连接管理（WAL、busy_timeout、schema 创建、迁移执行）
- `migrations.rs` — pre/post 两阶段迁移（雪崩 ID、模式迁移）
- `paths.rs` — `~/.snowapp` 路径解析
- `services/` — 按领域拆分的数据访问层（37 个模块，见数据存储文档）

## 6. 启动流程

```
Electron 启动
  → bootstrap.ts
      1. 单实例锁（app.requestSingleInstanceLock）
      2. app.name = "Snow App"
      3. 初始化 native 绑定（loadNativeBridge，raw 调用避免死锁）
      4. initializeApplicationServices → 创建 ~/.snowapp + snowapp.db
         + 迁移 + 播种默认值 → markStorageReady
      5. 应用持久化主题 → 创建主窗口
      6. 注册 IPC handlers / 协议 / 托盘
  → 窗口就绪（此时 native 调用已可通过 storageReady 门控安全执行）
```

## 7. 数据流（一次 AI 对话）

```
用户发送消息
  → renderer: ChatInputView → conversationApi.sendMessage
  → main: chatHandlers → native.api 流式调用（anthropic/gemini/...）
  → native: agent loop（模型迭代 → MCP 工具调用：bash/grep/filesystem...）
  → 事件推送: sessionProxy → renderer（useAgentLoop 消费）
  → 落库: storage::store_chat_exchange → snowapp.db
  → UI: 消息渲染 + 流指标（run 级 token/耗时）+ 文件变更追踪
```

## 8. 关键设计决策

| 决策 | 理由 |
|------|------|
| 数据库放 Rust 侧 | 性能（避免 IPC 往返）、事务原子性、单进程内缓存路径 |
| storageReady 门控 | 首屏秒开：窗口不等数据库，调用自动排队 |
| 渲染层零 Node | 安全边界：contextBridge 只暴露白名单 API |
| MCP 服务器内置于 native | 工具执行贴近系统（进程/PTY/文件），避免 JS 层中转开销 |
| 单文件 SQLite + WAL | 备份简单（拷贝即备份）、读写并发友好 |
| 三语言 i18n 同步 | zh-CN / en / zh-TW 三个文件必须同时更新 |
| 事件驱动流式输出 | sessionProxy 中转保证多窗口/多会话隔离 |
