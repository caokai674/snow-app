# 8-第三方配置导入

Snow App 可以扫描并导入其他 AI 编码工具（Codex、Claude Code、OpenCode）的配置，
也可以安装和管理声明式插件（Plugin）。本文介绍 **设置 → 第三方配置**
（设置页 id：`import-settings`）页面的使用方法。

该页面包含两个标签页：

| 标签页 | 说明 |
| --- | --- |
| 导入配置（Import configuration） | 从 Codex / Claude Code / OpenCode 扫描并导入 MCP、Skills、Prompts、Commands、Agents、Plugins |
| 管理插件（Manage Plugins） | 管理已导入的插件（启用 / 禁用 / 更新 / 卸载 / 运行），以及从插件市场安装插件 |

## 1. 导入配置

### 1.1 支持的来源

页面顶部可以切换来源（Codex / Claude Code / OpenCode）。Snow App 会自动扫描
以下位置，并列出可导入的候选（Candidate）：

| 来源 | 配置目录 | 扫描的配置文件 | 可导入内容 |
| --- | --- | --- | --- |
| Codex | `CODEX_HOME` 环境变量或 `~/.codex` | 全局 `config.toml`；项目 `<项目>/.codex/config.toml` | MCP servers、`AGENTS.md` / `AGENTS.override.md`、profile 提示词、Skills、Plugins |
| Claude Code | `CLAUDE_CONFIG_DIR` 环境变量或 `~/.claude` | `~/.claude.json`、`~/.claude/settings.json`；项目 `.mcp.json` | MCP servers、`CLAUDE.md`、rules、commands、Skills |
| OpenCode | `OPENCODE_CONFIG_DIR`、`$XDG_CONFIG_HOME/opencode` 或 `~/.config/opencode`（兼容遗留 `~/.opencode`） | 全局 `config.json` / `opencode.json` / `opencode.jsonc`；项目 `opencode.json` / `opencode.jsonc` / `.opencode/opencode.json` / `.opencode/opencode.jsonc` | MCP（`mcp` 字段）、`instructions`、commands、agents、Skills |

每个来源标签下会显示：

- **汇总卡片**：MCP servers（全局 / 项目数量）、Skills、Prompts、插件或项目配置数量；
- **候选列表**：可勾选的导入项；
- **源文件**：实际扫描到的配置目录与配置文件路径，以及是否找到；
- **警告**：扫描过程中发现但不影响使用的提示（如不支持的 MCP 传输方式）。

### 1.2 候选状态

| 状态 | 含义 |
| --- | --- |
| New | 新的候选，可以导入 |
| Already effective | 已生效（例如 Skill 已在 Snow 扫描的路径内），无需导入 |
| Update available | 已导入过，但源内容有更新 |
| Conflict | 多个来源使用相同逻辑 ID 但内容不同，只能选择其中一个 |
| Unsupported | 无法导入（详见下文"不支持的项"） |
| Managed | 已由 Snow 托管且内容一致 |

### 1.3 执行导入

1. 切换到目标来源标签页；
2. 点击 **Refresh discovery** 重新扫描（可选，页面打开时会自动扫描）；
3. 勾选要导入的候选（Conflict 候选互斥，只能勾选一个）；
4. 点击底部 **Import selected (n)** 按钮。

导入完成后会显示汇总：导入（imported）、未变化（unchanged）、跳过（skipped）、
不支持（unsupported）的数量。

### 1.4 导入目标

| 候选类型 | 导入目标 |
| --- | --- |
| MCP server | Snow 的 MCP 设置（保持全局 / 项目作用域） |
| Skill | 复制到 `~/.snow/skills`（全局）或 `<项目>/.snow/skills`（项目），由 Snow 托管 |
| Prompt / Command / Agent | 系统提示词（System Prompt） |
| Plugin | 插件管理（由 Snow 托管其组件） |

### 1.5 去重与冲突规则

- 内容完全相同的来源会被合并为一个候选，并标注所有来源（shared）；
- 相同逻辑 ID 但内容不同的来源会产生 **Conflict**，只能选择其中一个内容变体；
- 提交前应用会重新扫描一次；若候选已发生变化，会要求先刷新再提交。

### 1.6 不支持的项

- Claude Code 的 WebSocket（`ws`）与 SSE（`sse`）MCP server；
- Claude Code 使用 `headersHelper` 的 MCP server；
- 既没有 `command` 也没有 `url` 的插件 MCP 声明。

## 2. 管理插件

在 **管理插件** 标签页可以管理由 Snow 托管的声明式插件。插件声明在
`marketplace.json`（或 `.agents/plugins/`、`.claude-plugin/`、`.codex-plugin/` 下的
`marketplace.json`）中，Snow 只读取其声明式组件（MCP、Skill、Prompt、Command、
Agent、Hook），**不执行安装脚本**。

### 2.1 已安装插件

| 操作 | 说明 |
| --- | --- |
| 启用 / 禁用 | 切换插件开关，禁用时其组件不再生效 |
| 更新 | 插件有更新（状态为 Update available）时重新拉取最新版本 |
| 卸载 | 移除插件及其 Snow 托管的组件 |
| 运行时 | 插件可声明 runtime（独立工具进程）。启动前会确认请求的权限（Plugin storage、Network、Child process），只运行可信代码 |

展开插件可查看其组件列表、来源路径与运行时信息。

### 2.2 插件市场

点击 **Add marketplace** 添加市场，支持以下来源：

| 来源格式 | 示例 |
| --- | --- |
| 本地路径 | `./my-marketplace`（目录内需有 `marketplace.json`） |
| GitHub 仓库 | `owner/repo` 或 `owner/repo@ref` |
| Git URL | `https://github.com/owner/repo.git#ref` |
| HTTPS 清单 URL | `https://example.com/marketplace.json`（必须 HTTPS，且直接指向清单文件） |

市场添加后：

- 市场缓存保存在 `~/.snow/plugin-marketplaces`，安装的插件保存在
  `~/.snow/plugins/marketplaces`；
- 选中市场可查看其插件目录（catalog），点击 **Install Plugin** 安装；
- 已安装的插件会显示开关，可在此直接启用 / 禁用 / 更新；
- 移除市场会删除其 Snow 缓存，**已安装的插件会保留**。

> 安全提示：只从可信来源安装插件。Snow 不会执行插件的安装脚本，但启用插件
> 的运行时等于运行外部代码，请确认其权限请求。

## 3. 托管资源与释放

导入的 MCP、Skill、Prompt / Command / Agent 都由 Snow 记录为托管资源
（存在 `~/.snow` 中，含来源路径与内容哈希）。若来源内容发生变化，候选会显示
**Update available**；确认后重新导入即可更新。

删除托管资源时：

- **Skill**：仅允许删除 `~/.snow/skills` 或项目 `.snow/skills` 内的目录（防止误删源文件）；
- **MCP**：从 Snow 的 MCP 设置中删除对应条目；
- **Prompt / Command / Agent**：从系统提示词中删除对应条目。

## 4. 常见问题

| 症状 | 原因与处理 |
| --- | --- |
| 来源显示 Source not found | 对应工具尚未安装或从未使用；安装并使用一次后重新刷新 |
| 候选状态一直是 Unsupported | 检查警告中的具体原因（如 MCP 使用了 ws / sse 传输） |
| 提交时报 Import discovery changed | 候选在扫描后被修改，点击 Refresh discovery 后再提交 |
| 多个来源内容相同却重复显示 | 相同内容的来源会合并为一个候选，仅在来源处列出多个工具 |
| 市场添加失败 | 确认是本地路径、`owner/repo`、Git URL 或 HTTPS 的 `marketplace.json` 直达链接 |
